# 09 — JIELI 外围硬件回归

**优先级：** P2。  
**依赖：** 00 基线；分别获得 AC792N/WL83 和 AC791/WL82 硬件窗口。两项可由不同硬件任务先后完成，但每块板/端口仍单人独占。

## 目标与当前证据

验证仍缺物理证据的 AC792 PWM 输出通道和 AC791 UART1 接收，而不是重新检查已经能编译的适配代码。

- AC792N：平台 PR #43 增加按需通道映射；当前记录 CH1 已验证，PWM CH0/2/3 仍需示波器/LED 波形实测。LED 仅证明开关，不足以证明频率/占空比准确。
- AC791/WL82：平台 UART1 TX 已验证，RX 尚未验证；另需核对日志 UART 与 UART1 的端口冲突，接收 IRQ 向量配置依赖平台 #43 的 `IRQ_UART2_IDX` 修复。

## 允许修改范围

- 允许为验证新增隔离的测试例程/配置，例如 `examples/peripherals/pwm/`、`examples/peripherals/uart/` 中的 JIELI 测试配置；允许修改 `platform/JIELI` 对应 PWM/UART adapter 或 board config 以修复本任务确证问题，限于这些具体外围路径。
- 失败时先记录复现、源码/波形证据，再做与该问题直接相关的最小修复；不混入无关重构或其他外设修复。
- 硬件一次只可由一个人占有；不得与 OTA、语音或摄像头测试并行访问同一板/串口。

## 步骤与验收

1. 登记 PCB revision、flash/build SHA、当前 pinmux/端口配置、仪器/逻辑分析仪接法、串口设备身份和任务时间窗；确认现场可恢复固件。
2. AC792：每个 CH0/2/3 分别设置低/中/高占空比与已记录频率，记录 pin、周期、高/低时间、占空误差、停止/重开行为及配置；用示波器/逻辑分析仪截图或 CSV 验证，无波形则判失败。
3. AC791：做 UART1 外部 TX→RX loopback 和独立外部发送→设备接收；先确认串口号/波特率/IRQ/pinmux 没与 console 冲突，记录字节序列、长度、丢字节/错误统计及多长度连续传输结果。
4. 复测原本已通过路径（如 PWM CH1 或 UART1 TX）以确认未回归；说明每个结果属于编译、信号波形还是协议数据层。
5. 结束时恢复并交接板卡/线束/串口占用；附固件 SHA 和现场枚举到的设备端口名。

**通过条件：** AC792 三个通道各有物理波形数据；AC791 RX 对已知测试流无丢字节/错误且可重复；board config 与测量针脚一致；回归路径正常。构建或发送命令成功不等于接收/波形通过。

## 停止条件与交付

设备版次、pin、console 冲突、外部串口和恢复方案未确认时停止接线/烧录。交付仪器截图/CSV、接线示意、固件 SHA、配置、串口枚举结果和错误日志。不得以别的板/别的 COM 编号代替。

## 共用规则

遵守 `README.md`：先通过 00；保护主仓与嵌套平台 dirty；硬件任务单人排队，显式交接；每次现场核实端口号，严禁照搬其他项目 COM21。本任务允许范围内可直接做最小修复并验证；不提交/推送/发布远端，除非本次派发明确授权。
