## 4. 摄像头（05）详解

### 4.1 J1 DVP（GC2145）— 已完成

- 实现：标准 `tkl_dvp` v2 拉模式；ISP overlay 缓冲必须用 **32 字节对齐静态 BSS 数组**（堆缓冲会触发 ISP 中断 AXI 异常）；采集任务只做 `GET→flushinv→memcpy 到 2 槽 staging→CLEAR`，独立 `cam_proc` 转 planar YUV422P→packed YUYV 并投递 TDL；示例把 320×240 每行写两遍铺满 320×480。
- 实机证据（连续三次递进，均 AC791 + GC2145，320×240@20）：
  - 平台 `660f2f59`：91.6 s / 2,700 帧 / drops=0 / 0 异常；`dvpfill` 由用户目视确认满屏。
  - 平台 `6562c41`（生命周期/内存加固）：129.8 s / 3,720 帧 / drops=0 / 0 异常。
  - 平台 `52b1322`（当前头）：133.4 s / 3,820 帧 / drops=0 / 0 异常，≈28.6 fps，95 条非致命 `isc bandwith err`，结束仍枚举。日志 `logs/serial-COM8-20261118-161028.log`。
- 代码位置：平台 PR #47 `camera/ac791-clean` @ `720bb6b0`；应用 PR #2 `camera/tdd-refactor` @ `8eecd3a0`；显示 TE 引脚修复 PR #6 @ `83c7407a`（未合入前单独构建需带上，否则 `display init rt=-2`）。
- 尚未覆盖：`tkl_dvp_stop` join 超时、`cam_proc` 创建失败等错误分支无法不离注入故障地实机触发，仅代码级验证。
- **2026-11-19 结构变更（已实机验）**：传感器所有权从厂商 `video0` 翻给 TDD（应用 `13af27fe`/`f183c80d`/`fb0b72b5`/`85174cf3`，平台 `24003fe3`/`e2413586`/`15f00ae5`），与 SPI 路径同形——板级 `BOARD_CAMERA_*` 注册 `tdd_camera_dvp_gc2145_register()`，平台只留 ops 全空的 `GC2145_TIMING` 时序描述符，DVP 构建剔除厂商 `gc2145_dvp/gc2145.c`，传感器跑板级几何 640×480@20、TKL 按 `step_x/step_y` 抽取交付 320×240。首轮上板踩到三处接线级问题（传感器时钟要等 video0 open、描述符漏 `.sync_config`、`yuv_order` 默认 UYVY），修好后 **35.3 s / 571 帧 / drops=0 / ≈17.6 fps、零 `video_ioct`/`isc line err`，画面与颜色用户目视正常**（`logs/serial-COM8-20261119-135349.log`，镜像 `dvp-tdd-final-96603c26.bin`）。镜像构建时必须带 PR #6 的 TE 修复；J1/J4 不能同时插。

### 4.2 J4 SPI（GC0310）— 已完成

- 已实现：SPI2 逐行中断 + DMA 行拷贝；640×480 packed 流解析（行首/行尾 tag、`tag_err=0`）；主机侧 2:1 抽取交付 320×240；GC0310 由 TDD 经软件 IIC(PH0/PH1) 配置，不再打开 video1。
- 2026-11-17 实机：4.44–4.84 fps、481 行/帧、`tag_err=0`、85 s 无复位；10 分钟长稳 frames=3297、0 复位。

- 离线审计结论（历史）：厂商 video1 打开路径不写表外寄存器；SPI 行框/载荷偏移与厂商逐字节一致；显示转换的 YUYV/UYVY 与 RGB565 交换实现正确。

  - 清理后实机：175 s / 776 帧 / 4.43 fps / 480.0 行/帧 / `tag_err=0`（`logs/serial-COM8-20261118-190828.log`）；引脚改造后 60 s / 4.44 fps / `tag_err=0`（`logs/serial-COM8-20261118-192756.log`）。

### 4.3 双摄同时采集 — 硬件不可行

J1 DVP 与 J4 SPI2 共用 PA2/PA3/PA4 与 PH0–PH3，且两模组同 I2C 地址 0x42；同时插会导致 vendor 探测误判并复位。验收口径应写成“单路可用 + 硬件互斥”，不能写成双路同时出图。

## 7. 如何继续（操作要点）

1. 构建（在示例目录）：先 `tos.py config choice -c <config>`（会 fullclean），再
   `.worktrees/05-camera/.venv/Scripts/python.exe .worktrees/05-camera/tos.py build -o <log>`，并设 `OPEN_SDK_PYTHON` 指向同一 venv。
2. **构建期间不要还原 `app_default.config`**：`tos.py build` 会按它重新配置，还原成仓库自带的 ESP32 默认值会让下一次构建误入 ESP-IDF。连续构建全部结束后再 `git checkout --` 还原。
3. 烧录/抓取：先开 `capture-791.ps1 -Seconds 200 -Port COM8`，再 `flash-791.ps1 -Image <preset>`；脚本会按 SHA 把 `images/` 里的归档镜像拷到 staging tools 后烧录。
   - 板卡显示 `VID_4C4A&PID_8057`（下载/UBOOT 态）时**无需断电**，直接在 staging tools 跑 `isd_download.exe` 即可烧录；烧完后设备会以 `VID_3654&PID_4155` 重启。
   - **不要跨烧录抓长稳**：抓取脚本在烧录前打开、跨过设备重启时，COM8 句柄会在重启后 20–40 s 静默（设备仍在跑）。长稳抓取请在设备启动完成后再开。
4. 头文件/配置改动后不要信增量构建，删除 `.build` 干净重建（曾出现 `vm_reset` 启动静默的假象）。
5. 平台 worktree 的 `platform/JIELI` 是指向 `.platform-worktrees/05-camera` 的 junction，改平台代码只在该 worktree 内。

## 8. 已知风险与坑

- SPI 帧缓冲来自 `tkl_system_malloc`（SDRAM），已在 CPU 读取前 `flushinv_dcache`（`52b1322`）；2026-11-18 SPI 实机验收通过（`tag_err=0`、零异常）。
- DVP overlay 缓冲必须是静态 BSS；换成堆会复现 `axi_rd_inv`。
- 两模组同插会误探针/复位；换模组务必断电。
- `isc bandwith err` 为非致命告警（约 1 条/s），不影响出帧。
- 串口/板卡单人独占；不要同时跑两个 capture 或烧录。
